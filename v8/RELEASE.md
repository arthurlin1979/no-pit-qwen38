# v8 版自述

Qwen3.8 Jinja 第八版（v8）。

## 適用版本（釘死）

- 推理引擎：Strata v0.2.13.1（含）以上，engine 0.1.59.1（含）以上。v8 用的 Jinja 語法（`~` 串接、`namespace` 跨迴圈累加）需 Strata 內嵌 Jinja 支援。
- 模型：Unsloth `Qwen3.8-Flash-Next-GGUF` 之 `UD-IQ4_XS-v31`，rev `d9620119`（全 hash `d96201194f103c906994f283f504209dc8d2a10c`，2026-11-04，4 碎片）。舊 rev `38bb39ee`（3 碎片）亦可用，觸發器與之無關。
- 同時適用：GSQ-RCO IQ3_S（5090／5094 同版 Strata 驗證）。
- 驗證硬體：5094（Ryzen 9 9900X＋RTX 5090 32G＋128G RAM）；5090 同配置。
- 專為 UD-Q4 新版處理：Q5_0 down 層需 `STRATA_PF_FUSED_Q50=1`（Linux 另加 `STRATA_PF_F16=1`），否則 prefill 慢一半；此為 serve 側環境變數，非模板事，但 v8 的 114／house 分數都在該 flag 開啟下測得。

## 動機

修 v7 的兩個觸發死角（114 實測：EXT-036、EXT-044）。

## 改了什麼（相對 v7，見 `v8_vs_v7.diff`）

1. 觸發範圍從「最後一句使用者訊息」擴大到「全部使用者訊息」。
2. 觸發訊號從只有 `json` 關鍵字，加上 JSON 骨架（`{"`＋`":`）與中文句式（只輸出／僅輸出／僅包含／只回傳／僅回傳）。
3. 有工具的對話也納入：對話裡已有 tool 結果（後半段、該收尾了）且任一句使用者訊息要 JSON，才上契約；第一輪（還沒動過工具）不受影響，SERIAL RULE 與工具格式保護照舊。

## 實測（5094，UD-IQ4_XS-v31，Strata，同 seed 同參數）

- EXT-036（有工具多輪）：FAIL→PASS，回 raw JSON。
- EXT-044（774 字無 json 字眼）：FAIL→PASS，回 raw JSON。
- v7 的 114 子集結論不變；v8 專治觸發覆蓋，規則本文一字未動。

## 追加覆蓋（2026-11-17，同 v8，不另編版）

- 程式碼題觸發：只輸出程式碼／僅輸出程式碼／只回傳程式碼／僅回傳程式碼／code only／source code only → 上 CODE 契約（只要本體，不准圍欄不准解說）。
- 更多中文句式：輸出以下／回傳以下。
- 工具分支加兩條：必填參數不准空字串；工具名必須一字不差用本名（禁 `tools.` 前綴，防照抄對話裡的寫法；Main 線 18 次拒收即此症，隔離＋毒化測試過）。
- 實測：V2-Q015 FAIL→PASS；程式碼題（EXT-038／040）圍欄消失回 raw code（功能分待 house code grader）；V2-Q013（無 ID 該拒調）不硬擋，屬模型行為。
- 追加：「實作＋def／函式／函數／class」觸發。抽驗功能全對（two_sum 5／5、longest_unique 4／4）；契約遵從有機率性，偶發圍欄。

## 已知限制

- 契約仍靠「看得出你要 JSON」觸發；完全不提格式、又要 JSON 的題面，模板看不出來，只能靠模型自己。
- 有工具＋全程無 JSON 暗示的題，不上契約（by design，保工具格式優先）。
