# v8 版自述

Qwen3.8 Jinja 第八版（v8）上線。修 v7 的兩個觸發死角（114 實測：EXT-036、EXT-044）。

## 改了什麼（相對 v7，見 `v8_vs_v7.diff`）

1. 觸發範圍從「最後一句使用者訊息」擴大到「全部使用者訊息」。
2. 觸發訊號從只有 `json` 關鍵字，加上 JSON 骨架（`{"`＋`":`）與中文句式（只輸出／僅輸出／僅包含／只回傳／僅回傳）。
3. 有工具的對話也納入：對話裡已有 tool 結果（後半段、該收尾了）且任一句使用者訊息要 JSON，才上契約；第一輪（還沒動過工具）不受影響，SERIAL RULE 與工具格式保護照舊。

## 實測（5094，UD-IQ4_XS-v31，Strata，同 seed 同參數）

- EXT-036（有工具多輪）：FAIL→PASS，回 raw JSON。
- EXT-044（774 字無 json 字眼）：FAIL→PASS，回 raw JSON。
- v7 的 114 子集結論不變；v8 專治觸發覆蓋，規則本文一字未動。

## 追加覆蓋（2026-11-17，同 v8，不另編版）

- 程式碼題觸發：只輸出程式碼／僅輸出程式碼／只回傳程式碼／僅回傳程式碼／code only／source code only → 上 CODE 契約（只要本體，不准圍欄不准解說）。
- 更多中文句式：輸出以下／回傳以下。
- 工具分支加一條：必填參數不准空字串；不知道就繼續幹活，不准送空字串佔位。
- 實測：V2-Q015 FAIL→PASS；程式碼題（EXT-038／040）圍欄消失回 raw code（功能分待 house code grader）；V2-Q013（無 ID 該拒調）不硬擋，屬模型行為。

## 已知限制

- 契約仍靠「看得出你要 JSON」觸發；完全不提格式、又要 JSON 的題面，模板看不出來，只能靠模型自己。
- 有工具＋全程無 JSON 暗示的題，不上契約（by design，保工具格式優先）。
